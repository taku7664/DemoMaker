# DemoMaker

기술 변경 사항을 설명하는 대신 **눌러 보게** 만드는 단일 HTML 데모를 작성합니다.

## 만들기 전에 정하는 것

1. **무엇을 보여 줄 것인가.** 한 데모는 주장 하나만 담습니다. 주장이 둘이면 파일을 둘로 나눕니다.
2. **왜 필요한가.** 지금 무엇이 문제이고, 그것이 누구에게 어떤 손해를 끼치며, 바꾸면 무엇이
   좋아지는지를 먼저 확정합니다. 이 답이 없으면 데모를 시작하지 않습니다.
3. **보는 사람이 조작을 해야 하는가.** 조건에 따라 결과가 달라지는 것이 핵심이면 조작을 두고,
   순서가 핵심이면 조작 없이 자동으로 재생합니다.
4. **어디까지가 연출인가.** 제품 코드를 그대로 옮길 수 없다면 규칙만 같게 줄여 쓰고, 줄여 썼다는
   사실을 파일 첫머리 주석에 밝힙니다.

> ⚠ **왜 필요한지 모르겠으면 지어내지 말고 물어봅니다.** 코드를 읽어도 이 변경이 왜 필요한지
> 판단이 서지 않으면, 그럴듯한 이유를 만들어 채우지 말고 `AskUserQuestion` 으로 요청한 사람에게
> 확인합니다. 무엇이 문제인지, 누가 불편을 겪는지, 무엇이 좋아지기를 기대하는지를 물으면 됩니다.
> 배경을 짐작으로 채운 데모는 나머지 내용까지 믿을 수 없게 만듭니다.

## 형식 고르기

| 상황 | 템플릿 |
| --- | --- |
| 조작이 필요한 좌우 비교 | `templates/demo-compare.html` |
| 조작이 필요 없는 자동 재생 | `templates/demo-auto.html` |
| 규칙을 경우별로 확인시키는 표 | `templates/demo-cases.html` |

## 화면의 차례

순서를 바꾸지 않고, 한 자리도 비우지 않습니다.

| 차례 | 자리 | 담는 것 |
| --- | --- | --- |
| 1 | 제목 (`h1`) | 무엇을 다루는지 알 수 있는 짧은 명사구 |
| 2 | 결과물 설명 | 이 화면이 무엇인지 한두 줄 |
| 3 | **목차** (`h2#toc` + `ul.toc`) | 아래 세 자리로 뛰는 링크를 세로로 나열. 링크 아이콘을 붙이고 파란 밑줄은 쓰지 않습니다 |
| 4 | **왜 필요한가?** (`h2#why`) | 문제 · 손해 · 바꾸면 좋아지는 것 |
| 5 | **데모** (`h2#demo`) | 조작 항목과 무대. 이 절만 들여쓰지 않고 폭을 그대로 씁니다 |
| 6 | **체크리스트** (`h2#checklist`) | 직접 확인할 것과 눌러 볼 것 |

## 작업 순서

1. 템플릿을 새 파일로 복사합니다. **파일 이름은 제목과 같게 짓습니다.**
   (보기: `그래프 로딩 UX 개선.html`)
2. 파일 안의 `[고칠 자리]` 표시를 처음부터 끝까지 따라가며 채웁니다. 표시를 다 없애면 초안이 끝납니다.
3. 첫머리 주석에 무엇을 보여 주는지, 어떻게 여는지, 어디까지가 연출인지를 적습니다.
4. `reference/STYLE.md` 의 점검표를 한 줄씩 확인합니다. 특히 빈 상태와 실패 상태를 직접 만들어 봅니다.
5. 브라우저에서 열어 콘솔에 오류가 없는지, 폭을 360px 까지 줄였을 때 한 칸으로 접히는지 확인합니다.

## 반드시 지키는 것

- **제목은 열다섯 자 안팎의 짧은 명사구입니다.** 「그래프를 여는 4초 동안 화면은 아무 말도 하지
  않는다」처럼 늘어놓지 말고 「그래프 로딩 UX 개선」 으로 줄입니다. 문제를 설명하는 일은 바로 아래의
  「왜 필요한가?」 가 맡습니다. 파일 이름과 `<title>` 도 그 제목과 같게 둡니다.
- **「왜 필요한가?」 절이 없는 데모는 내보내지 않습니다.**
- **절 제목에는 머리 기호를 붙이지 않습니다.** 소제목만 적고, 대제목 아래 목차에서 각 절로 뛰게 합니다.
- **마무리는 문단이 아니라 체크리스트입니다.** 확인할 것과 눌러 볼 것을 체크 상자로 두고, 각 줄
  아래에 왜 그렇게 만들었는지를 적습니다.
- 파일 하나로 완결됩니다. 외부 스크립트·글꼴·이미지를 불러오지 않고, 서버를 요구하지 않습니다.
- 둘째 줄에 `<!-- Copyright: DemoMaker (c) 2026 -->` 를 둡니다. 참고한 자료의 저작권 줄을 그대로
  옮기거나 사람·조직의 이름을 적지 않습니다.
- 아무것도 누르지 않은 첫 화면이 이미 무언가를 말하고 있어야 합니다.
- 기다리는 중·비어 있음·실패·완료 네 상태를 모두 그립니다. 빈 화면을 남기지 않습니다.
- 셀 수 없는 것은 세지 않습니다. 총계를 미리 알 수 없는 구간에는 분모를 붙이지 않습니다.
- 번역투를 쓰지 않습니다. 낱말은 막지 않되 문장 구조는 한국어를 지킵니다.
- 권하는 말은 「~하세요」 로 씁니다. 「~하십시오」 는 쓰지 않습니다.
- 밝은 화면과 어두운 화면, 애니메이션을 꺼 둔 환경을 모두 지원합니다.

## 참고 자료

설치하면 이 파일 옆에 템플릿과 참고 자료가 함께 놓입니다. 경로는 이 파일을 기준으로 삼습니다.

- `templates/` — 복사해서 채우는 템플릿 세 종
- `reference/STYLE.md` — 규격 전문과 내보내기 전 점검표
- `reference/base.css` — 공통 스타일 원본. 데모의 `<style>` 안으로 복사해서 씁니다.

사용자가 `/demo-maker` 라고 부르거나, 데모를 만들어 달라는 요청에서 저절로 불려 나옵니다.
