표시 이름 규칙 정리

표시 이름을 짓는 규칙이 경우마다 어떻게 갈리는지 표 하나로 확인합니다. 각 줄은 입력 하나와 기대값 하나를 담고 있고, 전부 실행 을 누르면 실제 결과와 견주어 통과 여부를 매깁니다.

  • 데모

왜 필요한가?

지금은 표시 이름을 그대로 내보내기 때문에, 이름이 비어 있거나 공백만 있으면 목록에 빈 줄이 남고 아주 긴 이름은 옆 칸을 밀어냅니다.

그래서 보는 사람은 빈 줄을 고장으로 여기고, 같은 이름이 여럿일 때에는 어느 것을 고르고 있는지 가릴 수 없습니다.

바꾸면 빈 이름을 대체 문구로 채우고, 긴 이름은 줄이며, 겹치는 이름에는 번호를 붙입니다. 규칙이 경우마다 어떻게 갈리는지는 아래 표로 확인할 수 있습니다.

데모

판정 케이스 입력 기대 실제

체크리스트

  • 잘 되는 경우만 모아 둔 표는 규칙을 설명하지 못합니다. 빈 입력과 아주 긴 입력, 겹치는 입력이 나란히 있어야 규칙의 모양이 드러납니다.

  • 실패한 줄에는 판정만 칠하지 않고 기대값과 실제값, 그리고 어긋난 이유를 함께 적습니다. 판정만 붉게 칠하고 끝내면 보는 사람이 다시 물어야 합니다.

  • 아직 정하지 못한 경우를 표에서 빼면 정한 것처럼 보입니다. 사유를 적어 남겨 두어야 나중에 다시 꺼내 볼 수 있습니다.

  • 판정은 표에 적힌 기대값과 견준 결과이지 제품을 직접 부른 결과가 아닙니다. 회귀를 막는 일은 저장소의 단위 테스트가 맡습니다.
