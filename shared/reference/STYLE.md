# 데모 규격

DemoMaker 가 만들어 내는 모든 데모가 지켜야 할 규격입니다. 템플릿을 고르고 내용을 채운 뒤에는
마지막의 점검표를 한 줄씩 확인합니다.

## 1. 공통 전제

- **파일 하나로 완결됩니다.** 외부 스크립트와 글꼴, 이미지를 불러오지 않습니다. 파일을 그냥 두 번
  눌러서 열면 동작해야 하고, 서버나 빌드 과정을 요구하지 않습니다.
- **연출임을 숨기지 않습니다.** 실제로 서버를 부르지 않고 지연만 흉내 낸다면 파일 첫머리 주석과
  본문 마무리 문단에 그 사실을 함께 적습니다. 규칙만 제품과 같게 구현하고, 회귀를 막는 일은
  저장소의 단위 테스트가 맡는다는 것도 밝힙니다.
- **저작권 표시를 둘째 줄에 둡니다.** `<!-- Copyright: DemoMaker (c) 2026 -->`
- **첫머리 주석에 다음 네 가지를 적습니다.** 이 데모가 무엇을 보여 주는지, 어떻게 여는지,
  어디까지가 연출인지, 셀 수 없는 것을 왜 세지 않았는지.

## 2. 형식 고르기

| 상황 | 템플릿 | 특징 |
| --- | --- | --- |
| 조건에 따라 결과가 달라지는 것을 직접 만져 보게 해야 함 | `templates/demo-compare.html` | 조작 막대 + 좌우 비교 |
| 순서가 있는 과정을 보여 주고, 보는 사람이 아무것도 누르지 않아도 됨 | `templates/demo-auto.html` | 열면 자동 재생, 끝난 뒤 기록이 남음 |
| 규칙이 경우마다 어떻게 갈리는지 확인시켜야 함 | `templates/demo-cases.html` | 케이스 표 + 통과·실패 판정 |

한 데모에 두 형식을 섞지 않습니다. 비교와 케이스 표가 모두 필요하다면 파일을 나눕니다.

## 3. 글

- 제목은 명사구로 짧게 짓고, 도입부에서 **무엇이 문제였고 무엇을 눌러 보면 되는지**까지 말합니다.
- 좌우 비교에서는 왼쪽이 항상 「바뀌기 전」, 오른쪽이 「바뀐 뒤」입니다.
- 마무리 문단에는 **왜 이렇게 했는가**와 **이 화면의 한계**를 함께 적습니다.
- 셀 수 없는 것은 세지 않습니다. 총계를 미리 알 수 없는 구간에는 분모를 붙이지 말고 누적 수만 적습니다.
- 조작 항목은 결과가 눈에 띄게 달라지는 것만 남기고 넷을 넘기지 않습니다.

### 번역투를 쓰지 않습니다

번역투는 **문장 구조**의 문제이지 낱말의 문제가 아닙니다. 영어 낱말이 섞여 있어도 한국어 문장으로
읽히면 괜찮고, 전부 한글이어도 영어 구조를 베꼈으면 고쳐야 합니다. 그러므로 「영어 낱말이 있는가」가
아니라 **「서술어가 있고 행위의 주체가 보이는가」** 로 판단합니다.

**금지 — 아래 구조는 쓰지 않습니다**

| 쓰지 않는 구조 | 고친 문장 |
| --- | --- |
| 데이터가 로드되어집니다 | 목록이 도착합니다 |
| 사용자에 의해 선택된 항목 | 사용자가 고른 항목 |
| 3개의 항목을 가집니다 | 항목이 3개입니다 |
| 로딩에 대한 처리를 수행합니다 | 읽는 동안을 처리합니다 |
| 즉각적인 피드백을 제공합니다 | 무엇이 끝났는지 바로 알려 줍니다 |
| 확인하는 것이 가능합니다 | 확인할 수 있습니다 |
| 이 데모는 당신에게 차이를 보여 줍니다 | 이 화면에서 차이를 볼 수 있습니다 |
| 전체 데이터 로드 후 렌더링 처리 | 전부 읽고 한 번에 그린다 |

고치는 요령은 둘입니다.

1. **주체를 밝히고 능동으로 씁니다.** 무엇이 무엇을 하는지 적으면 피동과 「~에 의해」가 저절로
   사라집니다.
2. **동사로 끝냅니다.** 명사를 석 줄 쌓지 말고 서술어를 놓습니다. 다만 조작 항목의 이름표나 표의
   머리글처럼 짧은 이름 자리는 명사구로 두어도 됩니다.

**허용 — 낱말은 막지 않습니다**

다음은 그대로 씁니다. 억지로 옮기면 오히려 알아보기 어렵습니다.

- 그 분야에서 쓰는 용어: LSP, API, JSON, 커밋, 빌드
- 화면에서 굳어진 짧은 이름표: Before, After, PASS, FAIL
- 우리말과 외래어가 모두 통하는 말(로딩·읽기, 렌더링·그리기)은 어느 쪽을 골라도 되지만,
  **한 데모 안에서는 한 쪽으로 통일합니다.** 같은 것을 두 이름으로 부르면 보는 사람이 다른 것인 줄
  압니다.

## 4. 코드

- `<script>` 전체를 즉시 실행 함수로 감싸고 첫 줄에 `'use strict';` 를 둡니다.
- 익명 함수 대신 이름 있는 함수를 씁니다. 기록과 오류 화면에 이름이 남습니다.
- 규칙이 걸린 자리에는 **왜 그렇게 했는지**를 한국어 주석으로 남깁니다.
- 타이머는 모두 배열에 모아 두고 초기화할 때 한꺼번에 해제합니다. 해제하지 않으면 다시 실행할 때
  이전 재생이 겹쳐 보입니다.
- 사용자에게 보이는 문자열을 HTML 로 조립할 때에는 반드시 이스케이프를 거칩니다.

## 5. 어떤 상황에서도 깔끔하게

데모는 잘 되는 경우만 보여 주면 안 됩니다. 아래 다섯 가지 상태를 모두 그려야 합니다.

1. **아직 실행하지 않음** — 빈 상자 대신 「무엇을 누르면 되는지」를 문장으로 둡니다.
2. **기다리는 중** — 곧 채워질 자리를 뼈대(`.skel`, `.placeholder`)로 미리 잡습니다. 자리를 잡아
   두어야 내용이 도착할 때 화면이 밀리지 않습니다.
3. **보여 줄 것이 없음** — 항목이 0건이어도 빈 화면을 남기지 말고 그 사정을 말합니다.
4. **실패** — 지금까지 받은 것은 남겨 두고, 멈춘 이유를 덧붙입니다.
5. **완료** — 조작을 멈춘 뒤에도 결과가 그대로 남아, 화면을 갈무리하면 그것만으로 설명이 됩니다.

레이아웃이 무너지지 않게 하는 장치도 함께 지킵니다.

- 로그와 목록 상자는 높이를 고정하고 안에서만 넘치게 둡니다. 줄이 아무리 쌓여도 문서가 늘어나지 않습니다.
- 좌우 두 칸의 설명 길이가 달라도 아래 상자가 어긋나지 않도록 `.sub` 에 `min-height` 를 줍니다.
- 수치 자리에는 값이 없을 때에도 `—` 를 넣어 높이를 유지합니다.
- `overflow-wrap:anywhere` 와 `word-break:keep-all` 로 긴 경로가 들어와도 가로 스크롤이 생기지 않게 합니다.
- 밝은 화면과 어두운 화면을 모두 지원하고, `prefers-reduced-motion` 에서는 애니메이션을 끕니다.
